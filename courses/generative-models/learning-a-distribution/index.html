Learning a distribution

An AI image generator only ever sees a finite set of training images. What should it learn from them so it doesn’t just copy them?

Code and results

Most of the neural networks we meet first are trained to recognize things. We show one an image of a handwritten digit and it tells us which digit it is. Now imagine asking for the opposite. After seeing many handwritten digits, the network should draw new ones that nobody wrote. A network that does this is a generative model, and this course is about the mathematics that makes it work.

The figure below shows such a model at work. On the left are digits from MNIST, a standard dataset whose training set holds 60,00060{,}00060,000 handwritten digits. On the right are digits drawn by a generator, our word for a network that draws images, trained on that set. Almost none of them are copies of training digits.

That last detail is the heart of the problem, because copying would have been easy. A model that stores the 60,00060{,}00060,000 digits and returns one at random matches the training set perfectly, and we call it the copying model. It is useless, because it can only show digits we already have. What we want is harder to say. A generator should learn the process that produced the digits, and the training set is the only evidence about that process. This chapter is about what that asks of a network.

The learning problem

Before writing anything formal, we want an example we can look at. Images are a poor choice, since each one is a point in a space with hundreds of dimensions where no distribution can be plotted. So this chapter works with a much smaller example in which every sample is visible, namely 121212 points drawn at random on the unit circle. Think of the 121212 points as our training set and of the circle as the process that produced them, hidden from the model. The copying model returns one of the 121212 points. The model we want produces points anywhere on the circle, since that is where the 121212 came from.

Now the same situation in symbols. We observe nnn samples X1,…,XnX_1, \dots, X_nX1​,…,Xn​ drawn independently from an unknown probability distribution P∗\mathbb{P}^*P∗ on Rd\mathbb{R}^dRd. On the circle, d=2d = 2d=2, n=12n = 12n=12 and P∗\mathbb{P}^*P∗ is the uniform distribution on the unit circle. For images, each sample is a vector with one coordinate per pixel and colour channel, and ddd is the number of coordinates. A grey MNIST digit has d=28×28=784d = 28 \times 28 = 784d=28×28=784 and a CIFAR-10 photo has d=32×32×3=3072d = 32 \times 32 \times 3 = 3072d=32×32×3=3072. Three ways to describe a distribution

A network takes numbers in and gives numbers out, so it is not obvious how it can describe a distribution on Rd\mathbb{R}^dRd. The question is what those output numbers should be. Three answers are in common use.

The most direct answer asks the network for a density pθ(x)p_\theta(x)pθ​(x), a function that says how likely each image is. This is harder than it sounds. A density must be non-negative and integrate to 111, but a flexible neural network meets neither condition on its own. Forcing a network to output a normalized density restricts the architecture heavily.

Another answer drops the normalization. The network outputs a function that is only proportional to the density, or the gradient of its logarithm in xxx. That gradient is the score, and a one-dimensional case shows why it is convenient. For the standard Gaussian, log⁡p(x)=−x2/2−12log⁡(2π)\log p(x) = -x^2/2 - \tfrac{1}{2}\log(2\pi)logp(x)=−x2/2−21​log(2π), so the score is −x-x−x. At x=2x = 2x=2 it equals −2-2−2 and points back toward the centre, and the further we go the harder it pulls. In general the score points toward images of higher density. The normalizing constant (here the term with log⁡(2π)\log(2\pi)log(2π)) vanishes in the gradient, so the network has no normalization to enforce. The network only has to output a vector of the same size as its input, so the usual image architectures can be trained to estimate a score as they are. This freedom has two costs. The model no longer gives probabilities. Drawing a sample also takes many steps that follow the score, because the score only says which way to move. The last answer goes straight to what we are after. It never writes the density down. Instead it says how to produce a sample: draw random noise from a simple distribution, then pass the noise through a network that turns it into an image.

Generators and the pushforward

Both steps of this recipe get a name. The noise is a random vector ZZZ with a fixed distribution γ\gammaγ on Rk\mathbb{R}^kRk, usually the standard Gaussian N(0,Ik)\mathcal{N}(0, I_k)N(0,Ik​), which is easy to sample and has no parameters. The network that turns ZZZ into an image is the generator g:Rk→Rdg : \mathbb{R}^k \to \mathbb{R}^dg:Rk→Rd, a neural network with weights θ\thetaθ. One number in this recipe is still free, the latent dimension kkk. The circle generator needs a single latent number to produce a curve in the plane. One might expect a 784784784-pixel digit to need 784784784 random numbers. Far fewer are enough, because images are far from arbitrary points of Rd\mathbb{R}^dRd.

Images lie near a manifold

To see why, compare a digit with an image drawn at random. An image whose 784784784 pixels are drawn independently and uniformly at random looks like noise. Natural images obey regularities that such random images almost never satisfy. Neighbouring pixels usually have similar values, and the strokes of a digit form continuous lines of roughly constant width. Each of these regularities is a strong constraint. Together they confine natural images to a tiny part of Rd\mathbb{R}^dRd.

Within that part, natural images can still change, but only along few directions. If we change the slant of a handwritten 4 or the thickness of its strokes, every intermediate image is still a plausible 4. Most other directions of Rd\mathbb{R}^dRd, such as adding independent noise to every pixel, quickly leave the set of plausible digits. We have met this shape already. The circle sits in the plane, yet a single angle locates a point on it. Natural images lie near a surface of the same kind, thin and of low dimension inside Rd\mathbb{R}^dRd, which mathematicians call a manifold.

To use this idea we need to say what a surface of low dimension is. The requirement is local. Near any point of the surface, a few numbers should be enough to say where we are, and changing those numbers should move us smoothly along it.

Definition 4 (Manifold). A set M⊂Rd\mathcal{M} \subset \mathbb{R}^dM⊂Rd is an mmm-dimensional manifold if every point of M\mathcal{M}M has a neighbourhood in M\mathcal{M}M (the part of M\mathcal{M}M inside a small ball around the point) described by mmm coordinates. This means there is a continuously differentiable invertible map φ\varphiφ from an open subset of Rm\mathbb{R}^mRm onto the neighbourhood, with a continuous inverse and a derivative of rank mmm at every point.

The conditions on φ\varphiφ say that the coordinates vary smoothly and that no direction is lost. The circle is a 111-dimensional manifold, with the angle as coordinate. The surface of a sphere is 222-dimensional, with latitude and longitude as coordinates. No single pair of coordinates covers the whole sphere, since longitude breaks down at the poles and jumps along one meridian, which is why the definition only asks for coordinates near each point. In both cases the manifold sits in a larger space, but moving along it takes fewer coordinates than the space has.

With this word in hand, the claim about images takes one line.

Assumption 5 (Manifold hypothesis). The distribution P∗\mathbb{P}^*P∗ of natural images concentrates near a manifold M\mathcal{M}M whose dimension mmm is much smaller than ddd.

By concentrates near we mean that most of the probability lies within a small distance of M\mathcal{M}M. The manifold hypothesis is an assumption about data, so it has to be tested on data. Measurements on real datasets support it. The intrinsic dimension of a dataset is an estimate of mmm. Estimators rely on the fact that in dimension mmm the number of data points within distance rrr of a point grows like rmr^mrm. Pope et al. (2021) report 777 to 131313 for MNIST (d=784d = 784d=784), 131313 to 262626 for CIFAR-10 (d=3072d = 3072d=3072) and 262626 to 434343 for ImageNet (d=224×224×3=150,528d = 224 \times 224 \times 3 = 150{,}528d=224×224×3=150,528).1 In every case mmm is a few dozen at most, while ddd runs from hundreds to hundreds of thousands.

This is what makes a small latent dimension possible. With k≥mk \ge mk≥m latent dimensions, g(z)g(z)g(z) can move along M\mathcal{M}M as zzz moves in Rk\mathbb{R}^kRk, as the circle generator does with k=m=1k = m = 1k=m=1. The match is not exact. The data lie near the manifold, but a generator with k<dk < dk<d puts all its mass on a surface of dimension at most kkk. The next section shows what this difference costs.

Generators without a density

Putting all the mass on a thin surface looks harmless, but it has a consequence for training. The most common way to train a model, maximum likelihood, needs a density. A distribution P\mathbb{P}P on Rd\mathbb{R}^dRd has a density ppp when the probability of every region AAA is the volume integral P(A)=∫Ap(x) dx\mathbb{P}(A) = \int_A p(x)\, dxP(A)=∫A​p(x)dx, where ppp is a function with values in [0,+∞)[0, +\infty)[0,+∞). Maximum likelihood raises pθ(Xi)p_\theta(X_i)pθ​(Xi​) at every training image XiX_iXi​, so without a density it has nothing to raise. The circle generator has no density, since it puts all its probability on a curve and a curve has no area. The cause is not specific to the circle. It lies in a property that the usual neural networks share, and that rules out a density whenever k<dk < dk<d.

The idea is that a network cannot spread a low-dimensional input over a higher-dimensional space, because it can only stretch distances by a bounded factor. A map ggg is Lipschitz with constant LLL if ∥g(z)−g(z′)∥≤L∥z−z′∥\|g(z) - g(z')\| \le L \|z - z'\|∥g(z)−g(z′)∥≤L∥z−z′∥ for all z,z′z, z'z,z′, so two points never end up more than LLL times farther apart than they started. Networks built from linear layers and the usual activations (ReLU, SiLU, tanh) are Lipschitz. The bound does real work here. Without one, a continuous curve can pass through every point of a whole square, as the space-filling curves of Peano and Hilbert do.

We go through the argument slowly. The simplest case is k=1k = 1k=1 and d=2d = 2d=2, a generator that maps a segment of length 111 to a curve in the plane. The plan is to cover the curve with small squares and show that their total area can be made as small as we like. If we split the segment into NNN pieces of length 1/N1/N1/N, each piece becomes a stretch of curve whose points all lie within L/NL/NL/N of its starting point, because the network stretches distances by at most LLL. That stretch of curve fits inside a square of side 2L/N2L/N2L/N centred on the starting point. Together the NNN squares cover the whole curve, with total area N×(2LN)2=4L2N. N \times \left(\frac{2L}{N}\right)^2 = \frac{4L^2}{N}. N×(N2L​)2=N4L2​. A finer split means more squares, but their number grows like NNN while the area of each one falls like 1/N21/N^21/N2, so the total shrinks. Doubling NNN halves this area, so the curve can be covered by squares of total area as small as we like. So the curve has no area.

The same count works in any dimension. In general there are NkN^kNk pieces, each inside a box of volume proportional to N−dN^{-d}N−d, since each of its ddd sides shrinks like 1/N1/N1/N. Together they cover the image with a total volume proportional to Nk−dN^{k-d}Nk−d, which goes to zero whenever k<dk < dk<d. With k=1k = 1k=1 and d=2d = 2d=2 the exponent is −1-1−1, the halving we just saw. For k≥dk \ge dk≥d the count says nothing. A set that can be covered by an arbitrarily small total volume has volume zero (Lebesgue measure zero), like a curve in the plane.

The result only needs the Lipschitz bound on each bounded region, a weaker condition called locally Lipschitz. We can now state it in full.

Then the image g(Rk)g(\mathbb{R}^k)g(Rk) has volume zero in Rd\mathbb{R}^dRd. This settles what we said about the circle generator. Its derivative has norm 2πΦ′(z)≤2π2\pi\Phi'(z) \le \sqrt{2\pi}2πΦ′(z)≤2π​, since Φ′(z)≤1/2π\Phi'(z) \le 1/\sqrt{2\pi}Φ′(z)≤1/2π​. The same covering argument also tells us how small the latent dimension may be, the question left open two sections ago. For this we need a different notion of size, because volume in Rd\mathbb{R}^dRd cannot tell a long curve from a short one, as both have volume zero. We use mmm-dimensional volume, which is length for m=1m = 1m=1 and area for m=2m = 2m=2 (its formal name is the Hausdorff measure). Measured this way, a locally Lipschitz generator with k<mk < mk<m cannot cover an mmm-dimensional manifold. The count is the same as before. There are NkN^kNk pieces, each of mmm-dimensional volume proportional to N−mN^{-m}N−m, for the same reason as the boxes above. The image therefore has mmm-dimensional volume proportional to Nk−mN^{k-m}Nk−m, which goes to zero when k<mk < mk<m. A manifold of dimension mmm has positive mmm-dimensional volume, as a curve has positive length, so the image cannot cover it. A generator needs at least mmm latent dimensions for its image to cover the manifold. With fewer it can still come close to P∗\mathbb{P}^*P∗ in the Wasserstein distance of Chapter 2, which measures how far probability has to travel, as a curve can wind through a disk and pass near all of its points. Such a curve is long, so its Lipschitz constant is large.

The noisy model is still a pushforward. When the curve passes beside a training point, pθ(Xi)p_\theta(X_i)pθ​(Xi​) is small but not zero. It grows as the curve moves toward the point, so maximizing the likelihood pulls the generator toward the data. Diffusion models in Chapter 7 add noise at every step for the same reason. Chapter 2 takes the other route and looks for distances that make sense without any density.

The main runs of the next section use k=d=2k = d = 2k=d=2, where the proposition does not apply and a generator can spread its mass over an area of the plane. The section ends by repeating them with k=1k = 1k=1, where it applies.

What training produces

The sections so far say what a generator can represent. They say nothing about what training will produce. The circle generator is no help here, since it was written down from P∗\mathbb{P}^*P∗, which training never sees. To find out, we train generators on a few points of the circle and look at every sample. The question is whether they learn the circle or the points.

Each generator is a network with two hidden layers of the same width and SiLU activations, mapping R2\mathbb{R}^2R2 to R2\mathbb{R}^2R2. The width grows from 444 to 1,0241{,}0241,024 by factors of 444. The text follows widths 161616 and 1,0241{,}0241,024, while the Lab box at the end of this section lists all five.

Training needs a number to minimize. Here it is the maximum mean discrepancy (MMD) between the samples and the training points. MMD compares two clouds of points through a similarity kernel, a function κ\kappaκ of two points that is largest when they coincide and falls to nearly zero when they are far apart. It averages this similarity over pairs within each cloud and over pairs across the two clouds. The MMD is small when the two kinds of average agree.

The smallest case shows how this behaves. Put one point xxx in the first cloud and one point yyy in the second. Then MMD2=κ(x,x)+κ(y,y)−2κ(x,y)\mathrm{MMD}^2 = \kappa(x, x) + \kappa(y, y) - 2\kappa(x, y)MMD2=κ(x,x)+κ(y,y)−2κ(x,y). The two terms within the clouds are fixed at the largest value of the similarity. When x=yx = yx=y the term across the clouds cancels them and the result is 000. As yyy moves away that term fades, so the result rises toward twice the largest value. Larger clouds use the same three averages. Their formula is in the Going further box “Restricted distances with fast rates and blind spots” of Chapter 2. With the Gaussian kernels used here, MMD amounts to blurring each cloud into a smooth density and measuring how much the two blurred densities differ. The losses below report its square, MMD2\mathrm{MMD}^2MMD2.

I chose the MMD because it needs neither a density nor a second network trained alongside the generator. The first means it can train a generator with k=1k = 1k=1. The second means that the only training that can go wrong is the generator’s own.

Every generator trains for 100,000100{,}000100,000 steps. Every setting is repeated three times, each time with its own training points drawn from the circle, so a result that holds in all three does not depend on one lucky draw.

Going furtherWhy a generator cannot copy exactly

A set is connected if it cannot be split into two pieces that are separated from each other. The space Rk\mathbb{R}^kRk is connected, and so is its image by a continuous map. A Gaussian gives positive probability to every open set, so Pg\mathbb{P}_gPg​ puts mass near every point of the connected set g(Rk)g(\mathbb{R}^k)g(Rk). With n≥2n \ge 2n≥2 distinct training points, Pn\mathbb{P}_nPn​ sits on nnn separated points, which a continuous generator fed with Gaussian noise cannot produce exactly. It can still come arbitrarily close in the Wasserstein distance of Chapter 2, by sending almost all of its mass near the training points and keeping thin threads in between.

A low training objective alone cannot tell us much, because the copying model is exactly what scores best on it. So we judge each generator on 2,0002{,}0002,000 of its samples with three numbers.

  • The training loss is the objective itself, the MMD between the samples and the training points.
  • The test loss is the same MMD, measured against 2,0002{,}0002,000 fresh points from the circle that the generator never saw. It estimates how far the generator is from P∗\mathbb{P}^*P∗. Fresh points of the circle score 0.0020.0020.002 themselves, because 2,0002{,}0002,000 points are only a sample.
  • Copies is the share of samples that land very close to a training point. Picture a small disc around each training point, with a radius chosen so that a fresh point of the circle falls in one of the discs only 1%1\%1% of the time. A sample inside a disc counts as a copy, so fresh points score about 1%1\%1% by construction.

All three need only a held-out set, so later chapters report them on real images too. For the MNIST generator of the opening figure the share of copies is 0.20%0.20\%0.20%, which is why we could say that almost none of its digits are copies. Real test images score 1.15%1.15\%1.15%, so the generator sits below them. That is a warning sign of its own. Its digits sit slightly farther from the training images than real digits do, which means they lie slightly off the data.

Four sources of error

The circle runs missed P∗\mathbb{P}^*P∗ in different ways. The wide generator copied 121212 points and longer training made it worse, while more points fixed it. To compare such failures, and later those of other models, we need a common statement of the problem and a split of the error into its sources. We now have what we need for the statement.

Training on the circle required three choices. Training picks one network out of many, so we need a set of candidates, the model class. To pick well we need a way of saying how far the distribution of a candidate’s images is from the distribution of real images. That distance usually cannot be computed, so we also need a number computed from the training images that stands in for it. The statement below collects them with their symbols.

Problem 7 (Learning a generative model). We are given nnn samples X1,…,XnX_1, \dots, X_nX1​,…,Xn​ of an unknown P∗\mathbb{P}^*P∗, a model class G\mathcal{G}G of generators and a way D(P∗ ∥ Pg)D(\mathbb{P}^* \,\|\, \mathbb{P}_g)D(P∗∥Pg​) to measure how far the model is from the data (a distance or a divergence, Chapter 2). We look for g^∈G\widehat{g} \in \mathcal{G}g​∈G such that D(P∗ ∥ Pg^)D(\mathbb{P}^* \,\|\, \mathbb{P}_{\widehat{g}})D(P∗∥Pg​​) is small. Since P∗\mathbb{P}^*P∗ is unknown, g^\widehat{g}g​ is obtained by minimizing an objective Sn(g)S_n(g)Sn​(g) computed from the samples.

The later chapters are organised around these three choices. For each model they say which choices it makes, why its objective takes the form it does and what those choices cost. Some models pay with blurry samples (the VAE), some with unstable training (the GAN) and some with slow sampling (diffusion). These names are only labels until their own chapters. The course page lists them all.

The problem asks for a small error. To make it small we first need to know where the error of a trained model comes from. Check yourself

  1. The empirical distribution Pn\mathbb{P}_nPn​ fits the training set perfectly. Why is it a bad answer?

    Answer

    Sampling from it only returns training images, so it never produces a new one. The goal is to be close to P∗\mathbb{P}^*P∗, of which the training set is only a finite sample.

  2. Can a generator g:R2→R3g : \mathbb{R}^2 \to \mathbb{R}^3g:R2→R3 built from linear layers and ReLU activations define a distribution with a density on R3\mathbb{R}^3R3?

    Answer

    No. Such a network is Lipschitz, so by Proposition 6 its image g(R2)g(\mathbb{R}^2)g(R2) has volume zero in R3\mathbb{R}^3R3. All the mass sits on that set, which no density allows.

  3. MNIST has an intrinsic dimension between 777 and 131313. What does that suggest about the size of the latent space?

    Answer

    A locally Lipschitz generator needs kkk at least as large as the dimension of the manifold to cover it, so kkk should be at least about 777 to 131313. This is a lower bound. It does not say how many more dimensions training needs.

  4. In the circle experiment, which source of error limits the width-1024 generator trained on 121212 points, and what fixed it?

    Answer

    Statistical error. Its class can follow the circle, as the runs on 200200200 points show, but 121212 points do not show that the data lie on a circle. Its training loss is even lower than that of the true circle on the same points. More data fixed it, while longer training made it worse.

  5. On 121212 points, the width-1024 generator had a better test loss after 6,0006{,}0006,000 steps than after 100,000100{,}000100,000. Why?

    Answer

    The objective is minimized near the copying model, so training longer moves the generator toward the 121212 points and away from the circle. Stopping early leaves some optimization error, which here keeps it closer to P∗\mathbb{P}^*P∗.

Summary

We started with a model that fits its training set perfectly and teaches us nothing, the copying model. A generator should give us the distribution P∗\mathbb{P}^*P∗ behind the samples, even though the samples are all the evidence we have about it.

To represent P∗\mathbb{P}^*P∗, a generator pushes noise through a network. One latent number was enough to produce the circle exactly. Natural images also lie near a low-dimensional manifold, so a generator whose image covers that manifold needs at least as many latent dimensions as the manifold has, far fewer than the number of pixels. This economy creates a problem. A network with fewer latent dimensions than pixels puts all its probability on a set of zero volume, so it has no density and cannot be trained by maximum likelihood unless noise is added.

Training brought a second problem. On 121212 points every generator fitted the points better than the true circle did, the wider one copied more of them, and longer training pushed it further toward copying. With 200200200 points the same generators followed the circle. Failures like these trace back to four sources. They are the model class, the finite sample, the objective and the optimization.

All of this leaves the number that training minimizes still to be chosen. It has to say how far Pg\mathbb{P}_gPg​ is from P∗\mathbb{P}^*P∗, it has to be computed from nnn samples, and it has to make sense when Pg\mathbb{P}_gPg​ has no density. Chapter 2 compares the standard choices and shows which of them still work.
